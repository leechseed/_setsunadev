Verdict research: _tools/scanner/research.md

  • Scan with NAPS2. It is free and open source. It drives the ES-590W through Epson's own driver, over or , and it has a command line a script can call.
  • Read typed pages with plus a plain-text sidecar.. It is already installed.
  • Read handwriting with a vision model, not Tesseract. Tesseract cannot read handwriting. The new scan-reader agent reads the page images instead.
  • Keep ScanSmart as a fallback only. NAPS2 uses the same Epson Scan 2 driver underneath.
  • Keep every raw scan. Handwriting goes in at 300 dpi color, lossless. Nothing ever writes over the only copy.

ScanSmart: what's wrong from Epson's own docs; no user complaint threads found

  • It guesses file names. It reads a date and subject off the page, and Epson lists "Files are Named with an Old Date" as a known problem.
  • Its OCR fails on some pages. Epson's guide has a whole topic for characters not being recognized.
  • Cloud sending breaks. Epson lists that as a known problem too.
  • It wants a person at the screen. Its flow is review, then save. It has no hot folder and no command line that the research could find.
  • It is closed source. No script can drive it, so it can't sit inside a pipeline.

The agents .claude/agents/ · on the Roster

scan-reader Sonnet · MS

Reads the page images of one batch and writes a faithful transcript per document. It keeps Chief's spelling and marks unclear words as [?word?]. It never summarizes or fixes the text.

scan-filer Haiku · PS

Reads the text or transcripts and proposes a title, a written date, one bin, tags and BOLO ties per document, as filing.json. It never moves a file. The script applies the filing.
