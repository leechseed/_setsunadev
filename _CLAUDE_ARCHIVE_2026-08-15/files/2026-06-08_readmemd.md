# Desire Profile — Local Sync Kit

A self-contained, vault-native version of Mission Control where **`state.json` is the single source of truth** and both Claude Code *and* the dashboard read and write it. Claude Code is your coach; the dashboard is your live view. Edits flow both ways within a few seconds — no manual sync, no copy-paste.

## What's in here
```
desire-profile-sync/
├─ server.js                  zero-dependency Node server (static + state API)
├─ dashboard.html             the cockpit console (reads/writes state.json via the server)
├─ state.json                 ← the source of truth (Claude Code + dashboard both edit this)
├─ CLAUDE.md                  drives Claude Code: coach persona, method, sync contract
├─ Desire-Profile-Toolkit.md  ← drop your toolkit file in here (the full framework)
└─ README.md                  this file
```
> Put all of these in **one folder**. Add your `Desire-Profile-Toolkit.md` alongside them so Claude Code can reference the full method.

## Prerequisites
- **Node.js** — you already have it (Claude Code runs on Node). No `npm install`, no dependencies.

## Run it (one command)
```bash
cd desire-profile-sync
node server.js
```
Then open **http://localhost:8000**. It binds to `localhost` only — nothing is exposed to your network. `Ctrl-C` stops it.

## How the sync works
- **Dashboard → file:** every toggle, note, quiz result, idea, and synthesis edit POSTs the full state to the server, which writes `state.json` atomically.
- **Claude Code → file:** Claude Code edits `state.json` directly (guided by `CLAUDE.md`).
- **File → dashboard:** the dashboard polls every ~3s; when the file changes on disk (because Claude Code edited it), the console refreshes — without clobbering a field you're actively typing in.
- **Conflict guard:** writes carry the file's last-seen timestamp. If the file changed underneath (e.g. Claude Code wrote while you had the page open), the server returns the current state and the dashboard reloads instead of overwriting. Last-writer-wins only when there's no conflict.

The header shows **LINKED / SAVING / SERVER OFFLINE** so you always know the link state. If it says offline, the server isn't running — start it with `node server.js`.

## Daily use
1. `node server.js`, open the dashboard — see where you are, what's next, capture ideas.
2. In the same folder, run **`claude`** and say *"where am I?"* — it reads `state.json` + `CLAUDE.md`, orients you, and coaches one step at a time. As you make progress it writes back to `state.json`.
3. Glance at the dashboard anytime; it reflects whatever Claude Code (or you) changed.
4. Hit **Export Markdown Archive** whenever you want a portable snapshot for your vault.

## The coach
Lives in Claude Code, not the browser (the browser version's no-key model link was a Claude.ai-only thing). Claude Code is more capable anyway — it has the files, the toolkit, and write access. The dashboard's **Copy session kickoff** button just hands you a one-line prompt to paste in.

## Privacy
Everything stays on your machine in `state.json`, served on `localhost` only. This is sensitive — keep the folder wherever you keep private work (your vault is fine). **Reset Console** wipes `state.json` back to empty; export first if you want a copy.
