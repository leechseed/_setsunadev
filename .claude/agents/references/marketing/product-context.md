# Product context

Use this at the start of any new venture or campaign, before offers, outreach, pricing or copy. One short file holds the positioning every other task reads, so Chief does not repeat himself.

## Workflow

1. Look for an existing context file for the venture. If one exists, summarize it, list the last few changelog lines, and ask which sections to update.
2. If none exists, draft a first version from what the repo already holds (README, pages, notes), then ask "what needs correcting, what is missing?" Drafting first is faster than asking twelve questions.
3. Push for customer words, verbatim. Exact phrases beat polished descriptions because they match how buyers think.
4. Save, bump the version and add one changelog line saying what changed and why. A typo fix needs no bump.

## Sections to capture

1. Product overview: one line, what it does, the shelf it sits on, type, business model.
2. Target audience: who, the main problem, two or three jobs they hire it for.
3. Pain points: the challenge before finding you, why current options fall short, what it costs them, the feeling underneath.
4. Competition: direct (same fix), secondary (different fix, same problem), indirect (a conflicting habit), and how each falls short.
5. Differentiation: what alternatives lack, and why that matters to the buyer.
6. Objections: the top three and the answers. Also who is not a fit.
7. Switching forces: push (what drives them off the old way), pull (what draws them to you), habit (what keeps them stuck), anxiety (what worries them about switching).
8. Customer language: how they describe the problem and the fix, words to use, words to avoid.
9. Voice: tone, style, three to five personality words.
10. Proof: real numbers, testimonials, results. Mark anything unproven as missing.
11. Goals: the business goal and the one action you want people to take.

Skip what does not apply (personas matter only when several people share one buying decision).

## Tips

- Ask the sharp question: "What is the number one frustration that brings them to you?"
- Ask for an example when an answer is vague.
- Summarize each section and confirm before moving on.

## How the Command uses it

One context file per venture, kept in that venture's folder: BOLO 138 the productized offer, BOLO 135 the creator income report, the Kobra cart, and a future BoldVenture site. Every other reference in this folder reads it first. For adult-arm ventures the public file stays generic; detail goes in `_PRIVATE/`.
