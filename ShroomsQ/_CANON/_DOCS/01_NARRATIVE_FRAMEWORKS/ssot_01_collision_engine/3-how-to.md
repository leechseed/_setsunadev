# The collision engine: how-to

Terms are defined in the [reference](2-reference.md).

## Run a character-vs-setting collision

1. Fill both slices first: the character stack and the setting slice.
2. Set the scope as a ladder address or span, for example `tori × DCUS [OXO.primary.M2–M4]`.
3. Line up the twelve mirrored rows, Lx against Sx.
4. Classify each row with one contact: conjunction, trine, square, opposition or void.
5. Write the reading and the scene potential for each row.
6. Check the discrimination rule. If every row is hot, redo the classification.
7. Store the collision record beside the slices.

## Classify a row

1. Ask whether the two layers share a trait. If yes, mark conjunction.
2. Ask whether the place feeds the character. If yes, mark trine, and check whether the source is hostile. A hostile trine is a seduction.
3. Ask whether the two grind against each other chronically. If yes, mark square.
4. Ask whether they meet head-on with stakes stated. If yes, mark opposition.
5. If no drama arises, mark void. The source calls that a legal, informative result.

## Flag a canon gap

1. Notice a row where one side is thin in canon, as S2 WEATHER was.
2. Mark the row underpowered.
3. Write that the engine surfaced the gap. Treat the row as diagnostic, not drama.

## Seed a scene from a row

1. Pick a hot row from the collision record.
2. Open the scene card.
3. Add a `collision:` line naming the row.
4. If no row seeded the scene, write why the scene justifies itself.

## Record a situation ping

1. Name the situation: a setting state plus a social configuration.
2. Check which variables the chart marks as vulnerable.
3. Let plot_systems and the scene card decide when the ping fires.
4. Write the state diff on the character, keyed to the firing address.
5. Leave the baseline untouched.

## Join a pair to the storyform

1. Check whether the pair is the storyform's RS.
2. If yes, treat the composite chart as the RS throughline's astrological body.
3. Record the composite in the relationship table row.
