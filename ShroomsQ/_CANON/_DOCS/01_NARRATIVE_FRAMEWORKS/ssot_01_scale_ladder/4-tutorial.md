**Who it's for:** a new writer learning the ladder · **What it does:** descends the OXO address from storyform to beat · **Type:** tutorial

# Tutorial: descend the ladder to one beat

You will walk the source's own example address down five rungs. Keep the [reference](2-reference.md) open. This lesson writes no story.

## Step 1: start at the storyform

Write `OXO.primary`. This is R5. Its completion test: all four throughlines complete, Outcome and Judgment delivered.

## Step 2: add the movement

Append `.M2` to make `OXO.primary.M2`. This is R4. Its test: all four throughlines advanced one signpost and a driver turned the story. Note that movements are presentation containers and signposts are structural order.

## Step 3: add the sequence and scene

Append `.q3.s12`. You now name sequence 3 and scene 12. For the sequence (R3), the test is a question answered at the tail. For the scene (R2), the test has two parts: a value turn and the five commandments.

## Step 4: add the beat

Append `.b4`. The address is now `OXO.primary.M2.q3.s12.b4`. This is R1. Its test: something was tried, something answered, something is now slightly different. The tracking system reads this scene as `M2 · Q3 · S12`, and the beat as its `bar.beat` after the `|`.

## Step 5: add the Touchstone clause

Return to every rung you named. Add one clause to each test: and no in-scope Touchstone is breached. A unit that fails the clause is a breach, not a whole unit.

## Step 6: place a thread

Write a thread span: `tori.arc[OXO.primary.M1–M6]`. This is a character arc. It runs through containers. It is not one.

## Check yourself

You did it right if you can say why `M2` is a container and `tori.arc` is not. Containers hold. Threads change. The tracking system writes the same address as a time code. Chief ruled on 2026-10-05 that the time code is the one address.
