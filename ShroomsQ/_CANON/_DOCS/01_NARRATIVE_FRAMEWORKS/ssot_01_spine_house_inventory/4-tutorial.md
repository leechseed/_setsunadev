# Tutorial: follow the OXO storyform through three levels

You will trace one file through the inventory. Keep the [reference](2-reference.md) open.

## Step 1: find the file at L1

Open the L1 table. Find `_CANON_NODES/oxo-storyform.md`. Read its Holds cell: the ruled form, §§2 to 6 throughlines, §4 IC ruling, §9 engine canon. Read its Also cell: L2, L3, L6.

## Step 2: follow the Also cell to L2

Open the L2 table. You find `oxo-storyform.md` §9 there, the populated quad descent. The same file is also keyed beside `_CANON_NODES/oxo-storyform-engine.dsf`, the machine-readable storyform.

## Step 3: follow it to L3

Open the L3 table. Find `oxo-storyform.md` §1: the eight switches ruled with rationale, and Personal Triumph. The same file now appears at three levels.

## Step 4: read the machine file

Return to L2. The `.dsf` holds raw engine cell IDs. Finding 3 says a future tool can parse the storyform instead of re-typing it.

## Step 5: read the gap register

Find the validation report at L2. Its Holds cell says it names the missing throughline and signpost fields. The report is the inventory's own gap list.

## Step 6: read the correction

Go to the addendum. It says the first craft-shelf count missed 109 distills. Note what that teaches: a finding stays in the record, and the record carries its own correction.

## Check yourself

You did it right if you can name three levels where `oxo-storyform.md` appears and say why the Also column exists. The spine is a tree, and one file can serve many levels.
