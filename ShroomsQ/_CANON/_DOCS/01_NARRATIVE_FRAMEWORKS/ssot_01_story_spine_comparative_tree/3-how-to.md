# The story spine: how-to

Source: [📐 ssot_01_story_spine_comparative_tree.md](../../../_SSOT/01_NARRATIVE_FRAMEWORKS/📐%20ssot_01_story_spine_comparative_tree.md). Terms are in the [reference](2-reference.md).

## Give a library source a spine address

1. Find the level the source serves. Use the rival map or the branch shelves in the reference.
2. Open the source's entry in the library.
3. Set the `feeds:` field to the level, for example `feeds: [SPINE.L4]`.
4. Add a node path when you can name one, for example `SPINE.L2.OS.concern`.
5. Treat the notation as provisional. The source says Chief has not ruled the `SPINE.Lx` syntax.

## Design an IP against the spine

1. State the root claim as a Grand Argument: the approach, the problem, and whether it succeeds.
2. Assign each of the four throughlines (OS, MC, IC, RS) one Domain. Use each Domain once.
3. Descend each throughline through Concern, Issue and Problem.
4. Set the eight dynamics: Resolve, Growth, Approach, Style, Driver, Limit, Outcome, Judgment.
5. Read the ending matrix from Outcome and Judgment and confirm it is the ending you want.
6. Hand the storyform to plot_systems for scenes, beats and sequences. The spine stops at L4's floor.

## Place a rival craft model on the spine

1. Find the model's row in the rival map.
2. Read what it actually models and its verdict.
3. Find the level where it lands: L0 to L7.
4. Use the model only for that slice. A hero's journey describes the MC line, not the whole story.

## Plug a setting into the spine

1. Keep the setting as its own entity in domain 03. Do not add it as a spine level.
2. Open the touchpoint map.
3. Pick the spine level you are working at.
4. Use the touchpoint for that level: S12 at L2, S11 at L3, scene cards at L4. Then use the collision diagonal at L5, the Argue mode at L6, a genre-setting contract at L7.

## Decide whether a branch becomes a domain

1. Count the branch's shelf against its branches.
2. Check whether the branch has outgrown its shelf.
3. If it has, propose a new domain. Character and setting followed this path. Plot is next.
4. Wait for Chief's ruling on the domain number.

## Add a new lattice module or limb

1. Confirm the module is IP-agnostic. The lattice builds any story.
2. Validate it against The Outliers (OXO), the test bed.
3. Deliver one module per session, in Chief's ruled order.

## Cite a Touchstone against a spine scope

1. Choose the scope: universe, IP, story, movement, place or character.
2. Write the Touchstone as `TS book:number`.
3. Look up the id in the [Touchstones register](../ssot_01_touchstones_register/2-reference.md).

## Add a rival model to the rival map

1. Get Chief's ruling that the rival comes in. Chief rules each new rival in.
2. Add one row with the four columns: Model, Holdings, What it actually models, Verdict vs the spine.
3. List only held library ids in Holdings. Mark a missing book as not held.
4. Add a missing book to the acquisition gaps line.
5. Write the verdict so it names the spine level where the model lands.
