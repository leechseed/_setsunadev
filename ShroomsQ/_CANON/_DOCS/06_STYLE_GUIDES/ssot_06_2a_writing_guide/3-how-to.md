# SSOT writing guide: how-to

Terms are defined in the [reference](2-reference.md).

## Build the frame of a new SSOT document

1. Start line 1 with `---` to open the YAML.
2. Fill the YAML (see the next task), then close it with `---`.
3. Write the H1: 📐, then `ssot_`, then the name.
4. Add a linked table of contents.
5. Write one paragraph of purpose that defines the document's scope.
6. Write the body for the page's type (see below).
7. End with a tabular version history.

## Choose the body for the page's type

1. Name the page's type: concept, reference, how-to or tutorial.
2. For a concept page, write Core Methodology and at least two Examples.
3. For a reference page, write the facts as tables or entries.
4. For a how-to, write numbered steps.
5. For a tutorial, write one lesson start to finish.
6. Do not mix types on one page.

## Write the YAML header

1. Write each list in flow style: `[Value 1, Value 2]`.
2. Double-quote each wikilink: `"[[Document_Name]]"`.
3. Put a space after every colon.
4. Add `reader`, `doc_type`, `owner`, `state` and `reviewed`.
5. Keep `status` and `last_updated` for now.

## Mark a technical term

1. Find the first instance of the term in the document.
2. Make it **bold**.
3. Define it in the same sentence or the next.
4. Do not bold later uses. A reader's own marks use `==highlight==`.

## Review an SSOT document against the guide

1. Name the page's type.
2. Check the body against that type's rule.
3. Scan for hedges: "basically," "perhaps," "maybe." Strike each.
4. Check that the methodology reads in present tense and active voice.
5. Check line 1 is `---` and the YAML is flat-syntax.
6. Check the header fields are present.
7. Check the version history lists the change.
