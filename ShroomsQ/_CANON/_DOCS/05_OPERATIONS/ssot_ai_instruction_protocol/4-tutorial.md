**Who it's for:** a first-time operator running the SSOT master prompt · **What it does:** walks one raw concept through the four phases to a finished file header · **Type:** tutorial

# Run the master prompt once

You will take one raw concept through the four phases and check the first lines of the result. The source holds no full worked example, so this lesson uses a made-up concept. The concept is a one-line note about how a team files its weekly summaries. It stands for any raw note.

> **OPEN:** the source carries no worked example of a run.

## Step 1. Categorize

Ask where the note fits. It describes how work is done, so the category is `operations`.

## Step 2. Sanitize

Strip informal words from the note. Replace "don't forget to" with an imperative sentence.

## Step 3. Structure

Map the note to the frame (Purpose, Version History) and a body for its page type (06.2). A concept page carries two examples.

## Step 4. Refine

Search for hedges ("might," "basically") and remove them.

## Step 5. Name the file

Name it `📐 ssot_operations_weekly_summary_filing.md`. State the name first.

## Step 6. Check the top of the result

You see the filename, then a YAML block with `type: ssot_methodology`, `category: operations`, `applies_to: [OVEREXITOUT, ASTRO7EX, LAKAD]`, and `status: canonical`.
