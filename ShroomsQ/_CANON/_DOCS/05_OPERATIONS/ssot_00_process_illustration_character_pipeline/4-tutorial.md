# Follow one character through the pipeline

You will walk the four flows for one new Tier 3 character, using the source's own examples at each check. The source holds no single worked character, so this lesson uses the example values it gives at each step.

> **OPEN:** the source gives no single character walked through all four flows, so the lesson stitches its separate examples.

## Step 1. Lock the storyform

Open Dramatica and load the storyform. The status must read LOCKED. If it is a draft, lock it first. Extracting from a draft can invalidate the template later.

## Step 2. Fill the Dramatica Ingest (Flow A)

Copy the blank form. Fill the header. Then fill Section 1 from the Story Dynamics Report and Section 4 from the MC Theme Report. Then fill Sections 3 and 2 from the Character Report. Fill Section 6 because every character does. Log each report in Section 8. Derive at least one Touchstone for Section 9. Generate Section 10 last. Run the Section 11 checklist.

## Step 3. Build the chart (Flow B)

Place the Sun from Domain, Concern, and the modality grid. Check it encodes the identity axis. Place the Moon. If it feels too comfortable or too rational, it is wrong. Place the Ascendant, Mercury, Venus, Mars, and Saturn. You now hold seven signs and can stop at a minimum viable chart. Mark the template `minimum_viable` if you do.

## Step 4. Pass the gate (Flow C, Step 1)

Run the three components: seven checks, nine checks, eight checks. A `minimum_viable` chart gives a yellow light. Proceed, and tag chart-fed values `ASTROLOGY_PENDING`.

## Step 5. Test Tier 1

Assign CORE, VITAL, and SOCIAL. The source's example is CORE=13, VITAL=14, SOCIAL=10. You should read them as "smart, physically elite, socially unfiltered." If you cannot guess that outline, the numbers are wrong.

## Step 6. Compute and read the stats

Compute the derived stats. Read Truth Exposure Index and Collapse Risk first. If the stats feel wrong, change the layer values, not the stats.

## Step 7. Record a checkpoint (Flow D)

A fabula event hits the character. The source's example is a crash that kills a person the character is attached to. Pick the Trauma type. Create the checkpoint: the WOUND score rises, the attachment object changes, and the relationship record changes from `active` to `severed`. Update both at the same time.

## Step 8. Check yourself

Look at the Quick Reference table. You now hold a locked base record and a narrative event, so the row says Flow D. A second event means a second checkpoint, each diffed against the base record.
