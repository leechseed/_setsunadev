# Make your first SSOT document

You will take a methodology note through the five phases and fix one pasted YAML block. The source holds no worked instance, so the note here is a made-up methodology about checking file names. It stands for any methodology.

> **OPEN:** the source carries no worked example of a creation run.

## Step 1. Classify

Ask whether the note is a methodology. It describes a repeatable method, so it is. Had it been story content, it would go to `_AUTHORITATIVE/`.

## Step 2. Draft

Write the core method and two examples. Check each sentence: no "might," no "don't," present tense. Bold the first use of each technical term.

## Step 3. Initialize the YAML

Fill the template. Check that `type`, `category`, and `applies_to` appear.

## Step 4. Paste and check

Paste the YAML into Obsidian. Suppose it shows as a code block. Delete the first `---`, then type three dashes by hand at Line 1. The Properties UI appears.

## Step 5. Name and save

Name the file `📐 ssot_operations_file_name_check.md`. Save it in `_CANON/_SSOT/`.
