# File one document: the Development Standard

You will classify a document the way the ladder's first filing pass did. You will use a document the source files: the Development Standard. You finish with the rung, the tag line, and the table row.

## Step 1. Run the rule in order

Ask rule 1: does the document forbid nothing? No. The standard has nine standing rules with "shall"-style force, such as nothing builds before the order is confirmed. So it is not a handbook.

Ask rule 2: does it measure a product? No. It governs how the Command works, not what a product measures.

Ask rule 3: does it govern how the Command works? Yes. The rung is **procedure**.

## Step 2. Check the test

A procedure's "shall" must be testable against the transcript and the record. The standard's audit hooks table names where each rule's evidence lives, for example the transcript or BOLO.md. The test holds.

## Step 3. Write the tag

Put this first in the frontmatter, right after the opening fence:

`rung: procedure · NASA four, ruled 2026-09-15 (BOLO 50)`

## Step 4. Add the filing row

Add the row: the document, rung `procedure`, status `stamped`. The source's table lists this document with exactly that row.

## Step 5. Add the index row

Table 1 records what it governs: the build loop inside a session. Its Command parents are SOP, the project flow, DOCTRINE 0, and the standards register. It has no outside parent in the register.
