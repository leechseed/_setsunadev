# Project Flow: how-to

## Start a project (P0)

1. Name the two or three PIRs, the questions whose answers change the decision.
2. Scan the environment against those PIRs.
3. Write the problem statement.
4. Form the initial hypothesis.
5. Seed the command narrative: who the project is for and what story it joins.
6. Decide: project, BOLO, or nothing.

## Write the brief (P1)

1. Copy the blank brief from the reference page.
2. Write section 1 yourself, as the operator: end state, one intent sentence, and the mode (annihilation or erosion).
3. Ask the partner to draft sections 3 to 9 from the holdings.
4. Rule each drafted section.
5. Set the milestones (M-001 and on) as events, not dates.
6. Size the brief: five lines for S, one page for M, up to three pages for L.
7. File the brief in `_PRIVATE/` if it carries finances or persona internals. Otherwise file it in the domain folder.

## Run a gate

1. Wait for the phase event to fire.
2. Copy the gate checklist and fill the header with the gate number, project, date, and event.
3. Check the six boxes: entry criteria, assumption log, risks, attainability, ends and means, value.
4. Pick GO, NO-GO, or HOLD.
5. For a HOLD, write the blocker, the decider, and the conversion date. Never leave any blank.
6. Record the decision in the brief's decision ledger and in STATE.md.

## Add an assumption to the log

1. Add a row with the next ID (`A-00n`).
2. Fill the statement, category (Business, Environmental, Process, or Technical), impact, risk if false, and validation.
3. Set status to OPEN.
4. Review the row at every gate. Move it to VALIDATED, INVALIDATED, or REVISED.

## Pick a size for a piece of work

1. Call a BOLO, a tool, or a doc an S: write a five-line brief and run one gate at done.
2. Call a system build an M: write a one-page brief and gate at P1, P3, and P4.
3. Call a venture or IP release an L: write a brief up to three pages and gate every phase.

## Close a project

1. Confirm the exit criteria are true.
2. Run the P6 AAR: what happened, why, what applies next.
3. Update the registries.
4. Mark the brief complete.
5. Sweep the project's cards from oscar-mike.

## Run a weekly AAR (P4 and P5)

1. Answer three questions: what happened, why, what applies next.
2. Record the answers in writing. Never keep them verbal only.
