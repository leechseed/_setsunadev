# Documents style: how-to

Rule numbers refer to the [reference](2-reference.md).

## Start a new page

1. Pick the one job: doing or understanding (rule 1.1). If you need both, plan two pages.
2. Pick the type: tutorial, how-to, reference or concept (rule 1.2).
3. Write the page in order: concept, reference, how-to, tutorial (rule 1.3).
4. Add the header (see "Write a page header" below).
5. Write the body in the voice for the type (rule 3.5).

## Write a page header

1. Write the thin strip first: who it is for, what it does, and the type (rule 2.1).
2. In a markdown file, put the strip as the first body line.
3. Add owner, state and reviewed to the front matter (rules 2.2–2.3).
4. Set state to draft, ruled or retired.
5. Set reviewed to the date someone last checked the page against the truth.

## Review a page in passes

1. Put each sentence on its own line.
2. Pass one, facts: check each claim against its source.
3. Pass two, words: for each sentence, ask who acts and whether the verb is active. Ask whether any word can go. Ask whether a literal reader could take the wrong branch, and whether the key word is at the end.
4. Pass three, aloud: read the page out loud. Where you run out of breath, cut the sentence.
5. Run the script check for 20 words per sentence.
6. Update the reviewed date.

## Change a ruled page

1. Do not edit the page quietly.
2. Bring the change to Chief.
3. Wait for Chief to rule it.
4. Make the edit, then update the reviewed date.

## Write a troubleshooting page

1. Start from what the reader sees.
2. Write one entry per problem.
3. Make the heading the symptom, in the reader's words.
4. Under it, write the symptom, then the cause, then the fix (rule 4.1).

## Write a glossary

1. Write one entry per term.
2. Order the entries alphabetically.
3. Give each entry the term, a one-line plain meaning, and a link to where it is used.
4. For an old name, point to the current name (rule 4.2).

## Write a decision record

1. Put one decision on the page.
2. Date it and name who ruled it.
3. Write three parts: what we decided, why, and what we gave up.
4. Never edit it after the ruling.
5. For a later decision, write a new record that points back (rule 4.3).

## Order the ideas on a page

1. Write headings that state an idea, not a label such as "Background."
2. Name each list's order: argument, time, structure or importance.
3. Run the plural-noun test on each list.
4. Open with only what the reader already accepts.
5. Join sections with a hinge sentence that repeats the last key word (rule 3.6).

## Add a visual to a page

1. Pick one claim the page already makes in words (rule 5.1).
2. Pick the picture by the job: flow, tree, graph, state diagram, timeline, matrix or mind model (rule 5.2).
3. Place it by the page type. A concept page opens with a mind model. A reference page adds a structure diagram when its system has more than five components (rule 5.3).
4. Write the diagram as Mermaid in the Command's colors, in the page's static markup (rule 5.5).
5. Use the page's own words for the labels. Add no new fact.
6. Write a one-line caption that tells the reader what to look at (rule 5.4).
7. Check every box and arrow against the text before you call the page reviewed (rule 5.1).

## Find the reply rule you need

1. Open the reply table in the reference.
2. Find the rule by number or by its one-line text.
3. Read the full text in SOP.md §7. The table is a locator only.
