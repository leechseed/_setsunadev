# Documents style: write one page, start to finish

The source records one real worked case. On 2026-10-04 the writers applied the core to the SOI, the sit rep page and the DOPE SHEETs. This lesson follows the same moves on a small page of your own.

## Before you start

Pick one topic from the Command that you understand. Keep the [reference](2-reference.md) open.

## Step 1: choose the job

Ask whether your reader will skim for a step or read it through. Say you pick "read it through." That is an understanding job, so the type is concept (rules 1.1 and 1.2).

If you also want a recipe on the page, stop. That is a second page.

## Step 2: write the strip

Write one line:

```
**Who it's for:** … · **What it does:** … · **Type:** concept
```

Fill in the reader and situation, the one job, and the type. Rule 2.1 asks for exactly these three.

## Step 3: write the front matter

Add owner, state and reviewed (rule 2.2). Set state to draft. Set reviewed to today. These sit in the front matter of a markdown file, one click from the strip (rule 2.3).

## Step 4: write the body

Write headings that state ideas, not labels (rule 3.6). Use classic voice: one voice, state it, no hedges (rule 3.5). Define each term on first use. Keep each sentence to one idea with a named actor.

Put any rich description in one section at the foot, named "The long read" (rule 3.3).

## Step 5: review in three passes

Put each sentence on its own line. Check facts first. Check words second, with the five questions. Read aloud third, and cut any sentence that runs you out of breath (rule 3.4).

## Step 6: hand it on

The page stays at state draft until Chief rules it. After ruling, the page is never edited quietly. Chief rules each change, and the reviewed date updates.

You have now built one page the way the core asks. Next, write the reference page, then the how-to, then the tutorial (rule 1.3). The [how-to](3-how-to.md) has the steps for each other page type.
