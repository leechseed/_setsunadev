# Command Ladder: how-to

## Pick the rung for a document

1. Ask: does the document forbid anything? If it forbids nothing, file it as a **handbook** and stop.
2. Ask: does it measure a product? If yes, file it as a **standard**.
3. Ask: does it govern how the Command works? If yes, file it as a **procedure**.
4. Ask: does it say what the Command is and why? If yes, file it as **policy**. Do not add to the policy rung unless the document has earned it. Today the rung holds DOCTRINE 0 and nothing else.
5. If the document says what one specific product must be, add the **spec** tag on top of its rung.

## Tag a document

1. Open the document's frontmatter.
2. Put the line `rung: <rung> · NASA four, ruled 2026-09-15 (BOLO 50)` first, right after the opening fence.
3. If the document has no frontmatter, add a three-line block that holds only the tag.

## Tag a read-only file

1. List the file in the filing table with the status "read-only file, listed here only."
2. Stamp the tag the next time the file is opened for a change.

## Add a document to the filing table

1. Add one row: document, rung, status. Every core SSOT doc under `_SSOT/0*/` has a row, and a new one gets its row at birth (IF catalog call 9, ruled 2026-10-05).
2. Add a row to Table 1 with what it governs, its Command parents, and its outside parents.
3. Add the document to its level or world row in Table 3.
4. If it cites an outside body, add it to Table 2.

## File a document found without a tag

1. Note the untagged document.
2. File it at the next sit rep, using the rule that decides the rung.

## Read the gaps in the index

1. Open Table 3 and find an empty rung for the level you work on.
2. Check the "Gaps the index shows" list for a match.
