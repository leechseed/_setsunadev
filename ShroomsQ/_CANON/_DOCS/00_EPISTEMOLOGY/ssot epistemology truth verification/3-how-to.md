# Truth verification: how-to

Look up each framework in the [reference](2-reference.md).

## Check a claim in a story system

1. Name the system the claim belongs to: Narrative (01), Character (02), Setting (03), Plot (04), Theme (06), Style (07), Tracking (08) or Worldbuilding (05).
2. Find the system's row in "How the Frameworks Check the Systems".
3. Apply each framework named in that row to the claim.
4. If one framework cannot confirm the claim, add a second framework.
5. Run Skepticism and Critical Thinking on the claim.
6. Mark the claim checked if it survives. Mark it open if it fails.
7. Write the status and the frameworks that checked the claim on the claim's own record, in the doc that owns it. Do not write them in Tracking (08).

## Select frameworks for a research design

1. Identify the nature of the inquiry: empirical, logical, historical or other.
2. Look up the domain in the Truth Framework Selection Guide.
3. Pick the primary frameworks, then the secondary ones.
4. Apply several frameworks for cross-validation.
5. Note each framework's limits.
6. Document your epistemological assumptions.

## Verify a worldbuilding system

1. List every transaction or event the system produces in the narrative.
2. Map each one to the system's rules.
3. Record each contradiction as a coherence failure.
4. Test whether the rules produce the story tension you want. This is the pragmatic check.
5. Check that character behavior matches character profiles. This is the correspondence check.
6. Keep the system if all three agree. Revise it where they do not.

## Test a character's change of belief

1. State the premises that cause the change.
2. Research the psychology of that change. This is the empirical check.
3. Write the argument as a syllogism and test that the conclusion follows.
4. Compare the change with every scene of the character. This is the coherence check.
5. Judge whether the change produces dramatic tension. This is the pragmatic check.
6. Accept the change if all four agree.

## Add a Sources line to a framework

1. Find a source that supports the framework. Give the framework one or two library ids at most.
2. Check that each id qualifies. A qualifying id names a held library file. It is a BVX number or a subject code: PSY, TEC, MIL or MSX.
3. Add a line starting `Sources:` under the framework's Limitations.
4. If no source exists, write `method, no source` with the BOLO and date. The source does this for Frameworks 3 and 4.
5. Ask Chief to rule in any third source.
