# Pattern library: how-to

Entries live in the [reference](2-reference.md).

## Add a pattern entry

1. Name the pattern.
2. List its steps in order.
3. Name the tier where it runs: foundation, fabula, narratology or operations.
4. List the scales it runs at.
5. Add a proof line if it has run.
6. Mark any step names the CDR proposed and Chief has not ruled as provisional.

## Decide which half a doc belongs to

1. Ask what the doc answers.
2. If it answers what counts as true, it belongs to the Truth half. It checks.
3. If it answers what shapes repeat, it belongs to the Pattern half. It repeats.
4. Add the doc to the Pattern half list in the library.

## Place a cycle in its home

1. Identify the cycle: research, design or development.
2. File a research cycle in the Truth half.
3. File design patterns in the Pattern half.
4. File a development cycle in Operations.
5. Check the cycle runs the shared loop: try, check, adjust, repeat.

## Run the Command loop on a task

1. Chief speaks.
2. Capture the task to the BOLO.
3. Run recon.
4. Bring recs.
5. Take Chief's one-word ruling.
6. Build.
7. Run the script check.
8. Publish.
9. Log.

## Apply the change cycle to a scene, arc or era

1. State the want of the person or group.
2. State the push: what they do to get it.
3. State the cost the world charges.
4. State the change that results.
5. Feed the change into the next want.
6. Pick the tier: fabula for the world tick, narratology for the story beat.

## Stack one pattern on another

1. Ask Chief to decide each stack. This holds until the sim (BOLO 101) fixes a format.
2. Name the lower pattern and the upper pattern.
3. Name the scale each pattern runs at.
4. Feed the lower cycle's change into the upper cycle as its want or its cost.
5. Ask Chief to rule the stack in as a pattern entry.
